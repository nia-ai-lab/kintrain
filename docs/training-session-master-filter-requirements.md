# 実施画面「種目マスタ・絞り込み・実施済み表示」要件定義書

- 文書状態: 実装済み（未デプロイ）
- 作成日: 2026-08-09
- 対象画面: 実施画面（`/training-session`）
- 主対象端末: iPhone 16 Pro（縦向き）

## 1. 背景

現行の実施画面では、実在するメニューセットを1つ選択し、そのセットに登録されたメニュー項目だけを表示している。そのため、メニューセットに未登録のトレーニング種目をその場で実施したい場合、事前にメニューセットへ追加しなければならない。

また、メニュー項目数が多い場合の検索手段がなく、目的の種目を探すために長いスクロールが必要になる。対象日に実施済みの種目についても、実施元のメニューセットへ切り替えなければカードを表示できず、当日の実施内容をメニューセット横断で確認しにくい。

## 2. 本要件の理解

本改修では、次の4点を実現する。

1. 実施画面のメニュー選択欄から、全トレーニング種目を含む仮想的な `種目マスタ（全種目）` を選択できるようにする。
2. `種目マスタ（全種目）` は通常のメニューセットと同じ選択UIに表示するが、`TrainingMenuSet` および `TrainingMenuSetItem` のレコードは作成しない。
3. 表示中の種目を、種目名と使用器具のAND条件で即時に絞り込めるようにする。器具は検索可能な複数選択とする。
4. 対象日に実施済みのトレーニング種目だけを、実施元メニューセットに関係なく抽出して表示できるようにする。

本書では、「データベースに硬毛があるわけではない」という記載を「データベースにレコードを持たない」という意図として扱う。

## 3. 目的

- 予定外の種目でも、メニュー管理画面へ戻らず実施記録を開始できるようにする。
- 多数の種目から、片手操作と少ないタップ数で目的の種目へ到達できるようにする。
- 当日の実施内容をメニューセット横断で確認し、必要であれば同じ種目の追加記録を続けられるようにする。
- 現行の下書き、前回値入力、確認、最大12件保存などの安全な記録フローを維持する。

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| 実在メニューセット | データベースの `TrainingMenuSet` として保存されている恒常または一時メニューセット |
| 種目マスタ | ユーザーが所有する有効な `training` 種別の全 `TrainingMenuItem` |
| 仮想メニュー | 実施画面上だけに存在し、データベースにメニューセットとして保存されない表示範囲 |
| 対象日 | 実施画面の日付欄で選択されている日。必ず本日以前 |
| 実施済み | 対象日のトレーニング実績に、同じ `trainingMenuItemId` のエントリが1件以上存在する状態 |
| 基本母集団 | 種目名・器具フィルターを適用する前の、選択中の表示範囲に属する種目一覧 |

## 5. 対象範囲

### 5.1 対象

- 実施画面上部のメニュー選択UI
- トレーニング種目カードの一覧
- 種目名検索
- 使用器具の検索・複数選択
- 対象日の実施済み種目だけを表示する切り替え
- 仮想メニューから開始したトレーニング実績の下書き、確認、保存
- iPhone 16 Pro縦向きを主対象とするレスポンシブUI
- 必要なAPIレスポンスおよびフロントエンド状態の拡張

### 5.2 対象外

- 種目マスタの新規作成、編集、削除
- 実在メニューセットの作成、編集、並び替え
- 保存済み実績の編集または削除
- 誤字を推測する編集距離検索、意味検索、AI検索
- リカバリーメニューの全活動表示、器具検索、実施済み横断表示
- 1回の保存上限12件など、既存の実績登録ルールの変更
- 仮想メニューの日別計画への割り当て

## 6. 基本方針

### 6.1 トレーニングとリカバリーの扱い

本改修の新機能は `itemKind = training` のトレーニング種目を対象とする。リカバリーセットを選択した場合は、現行のリカバリー実施画面と挙動を維持し、種目名・器具フィルターおよび「実施済みのみ」は表示しない。

### 6.2 仮想メニューの非永続性

- `種目マスタ（全種目）` 用の `TrainingMenuSet`、`TrainingMenuSetItem`、日別計画を作成しない。
- フロントエンド内部では、実在IDと衝突しない列挙値で表示範囲を識別する。
- 仮想のメニューセットIDまたはメニューセット項目IDを、実績、下書きの永続データ、APIの保存要求へ実在IDとして書き込まない。
- 仮想メニューから保存した実績は `trainingMenuItemId` を保持し、実在メニューセット由来の項目ではないことを表現するため、`sourceTrainingMenuSetId` と `sourceTrainingMenuSetItemId` を付与しない。

## 7. 機能要件

### 7.1 表示メニューの選択

#### 7.1.1 選択肢

実施画面の「この日のメニュー」選択UIに、次を表示する。

- 有効な実在メニューセット
- 固定の仮想選択肢 `種目マスタ（全種目）`

`種目マスタ（全種目）` は実在メニューセットと同じ選択操作の中に表示し、`全種目` バッジまたは補助文で仮想的な表示であることを識別できるようにする。長い名称は1行で省略表示し、選択UI自体を横方向にはみ出させない。

#### 7.1.2 初期選択

既存の初期選択優先順位を変更しない。

1. URLまたはAPIへ明示指定された実在メニューセット
2. 対象日の `DailyTrainingPlan`
3. デフォルトの恒常トレーニングセット
4. 最初の有効な恒常トレーニングセット

`種目マスタ（全種目）` は自動選択しない。ユーザーが明示的に選択した場合だけ表示する。

#### 7.1.3 種目マスタの母集団

- 本人所有かつ有効な `itemKind = training` の全種目を対象とする。
- どのメニューセットにも所属していない種目を含む。
- 一時セットだけに所属する種目を含む。
- リカバリー項目を含まない。
- APIがページングされる場合、`nextToken` がなくなるまで取得し、先頭ページだけを「全種目」として表示してはならない。

#### 7.1.4 種目マスタ選択時のカード

- 種目名、筋肉ターゲット、使用器具、説明、直近実績、入力欄を表示する。
- メニューセット固有の処方がないため、「メニューセットの設定」および「設定値を入力」は表示しない。
- 直近実績がある場合は「前回値を入力」を使用できる。
- 直近実績がない場合も、重量・回数・セット数を手入力して記録できる。
- 種目マスタの管理順を基本順序とし、同順位の場合は種目名の昇順とする。
- 実在セット向けの `優先 n` は表示せず、必要に応じて一覧上の通し番号を表示する。

### 7.2 種目名フィルター

- ラベルは `種目名`、プレースホルダーは `種目名で検索` とする。
- 検索対象は `trainingName` のみとし、筋肉名、説明、器具名は対象に含めない。
- 入力途中から結果へ反映し、検索実行ボタンを必要としない。
- 文字列はUnicode NFKC正規化、英字の大文字・小文字の同一視、前後空白除去、連続空白の集約、ひらがな・カタカナの同一視を行う。
- 空白で区切った複数語は、すべての語を含む種目名に一致させる。
- 各語は部分一致とする。語順は問わない。
- 入力欄内のクリア操作で、種目名条件だけを解除できる。
- IME変換中は未確定文字による不安定な再描画を避け、変換確定後に検索結果を確定する。

### 7.3 使用器具フィルター

#### 7.3.1 選択UI

- 一覧上部に `使用する器具` ボタンを配置する。
- ボタン押下で、iPhoneでは下端から開くボトムシートを表示する。
- ボトムシート内に器具名検索欄と複数選択リストを表示する。
- 器具名検索は、器具の日本語表示名に対する部分一致とし、7.2と同じ文字正規化を適用する。
- 器具名検索は候補リストだけを絞り込み、すでに選択済みの器具を暗黙に解除しない。
- 候補は現在の基本母集団に存在する器具を優先表示し、各候補に該当件数を表示する。
- `適用`、`選択をクリア`、シートを閉じる操作を用意する。

#### 7.3.2 複数選択の判定

- 器具が未選択の場合は、器具条件を適用しない。
- 1件以上選択されている場合は、種目の `equipmentType` が選択値のいずれかに一致すれば器具条件を満たす。
- 複数器具間はOR条件とする。
- 選択中の器具は、一覧上部に削除可能なチップとして表示する。
- チップが横幅を超える場合は横スクロールとし、複数行へ無制限に折り返してカード一覧を押し下げない。

### 7.4 フィルター条件の結合

最終表示条件は次のとおりとする。

```text
表示対象 = 基本母集団
          AND 種目名条件（指定時）
          AND 使用器具条件（指定時）
```

- 種目名と使用器具はAND条件とする。
- `実施済みのみ` が有効な場合は、先に基本母集団を対象日の実施済み種目へ置き換え、その後に種目名と器具のAND条件を適用する。
- 絞り込み後の件数と基本母集団の件数を `12 / 84種目` の形式で表示する。
- `条件をクリア` により、種目名と使用器具を一括解除できる。
- メニューセットまたは表示範囲を切り替えても、画面を開いている間はフィルター条件を保持する。

### 7.5 実施済みのみ表示

#### 7.5.1 切り替え

- フィルター領域に `実施済みのみ` のトグルチップを配置する。
- OFFが初期状態である。
- ONの場合は、選択中の実在メニューセットまたは `種目マスタ（全種目）` に関係なく、対象日の全トレーニング実績から種目を抽出する。
- ONの間も元のメニュー選択状態を保持し、OFFに戻したときは切り替え前のメニューへ戻す。
- ONの間は `全メニューセット横断` と明示し、メニューセット内だけを絞り込んでいるように見せない。

#### 7.5.2 実施済みの集約

- 対象日の `GymVisit` に含まれるトレーニング実績を対象とする。
- 同じ `trainingMenuItemId` が複数回記録されている場合は、一覧カードを1種目に集約する。
- カードに `実施済み` バッジを表示する。
- 同日複数回の場合は `2回` のように件数を表示し、同日の最新実績値をカード上の当日実績として表示する。
- 並び順は対象日に最初に実施した時刻の昇順とする。
- 有効な種目マスタが存在する種目は、通常の入力欄を表示し、追加記録を開始できる。
- 種目マスタが無効化または削除済みでも、対象日の履歴スナップショットが存在する場合は履歴確認用の読み取り専用カードとして表示する。読み取り専用カードから新しい実績は開始できない。
- 実施済み表示は履歴の参照であり、表示、フィルター、解除によって保存済み実績を変更しない。

#### 7.5.3 日付変更

- 日付を変更した場合は、新しい対象日の実績から実施済み状態を再計算する。
- 本日以外の過去日でも同じ機能を使用できる。
- 対象日に実施済み種目がない場合は、`この日の実施済み種目はありません` と表示する。

### 7.6 下書きと保存

- 表示メニューの切り替え、フィルター変更、`実施済みのみ` のON/OFFによって入力済み下書きを破棄しない。
- 絞り込みでカードが非表示になっても、そのカードの下書きは保持する。
- 絞り込みにより下書き中のカードが非表示になった場合、一覧上部に `入力中 n件` を表示し、タップで入力中だけを確認できる導線を用意する。
- 仮想メニューから開始した下書きは、対象日と `trainingMenuItemId` を基準に識別し、仮想のメニューセットIDを必要としない。
- 同じ対象日・同じ種目について既存の入力中下書きがある場合、特殊表示から別の重複下書きを新規作成せず、既存下書きを表示・編集する。
- 実在メニューセットから開始済みの下書きを特殊表示で編集する場合は、元の実在メニューセット由来情報を保持する。
- 1回の保存上限12件、入力値検証、確認画面、確認画面からの除外・復元、保存処理は既存仕様を維持する。
- 確認画面では、仮想メニュー由来の項目に `種目マスタから追加` と表示する。ただし、その文言を実在メニューセット名として保存しない。

## 8. UI/UX要件

### 8.1 iPhone 16 Pro向け基準

- 主検証ビューポートは縦向き `402 × 874 CSS px` とする。
- 画面幅 `390〜430 CSS px` でも横スクロール、要素の重なり、操作不能が発生しないこと。
- `viewport` は `width=device-width, initial-scale=1` を維持する。
- Dynamic Island、Safariの可変ツールバー、ホームインジケータ、既存の下部ナビゲーションを考慮し、`safe-area-inset-*` を使用する。
- 主要タップ領域は44×44 CSS px以上とする。
- 入力文字サイズは16px以上とし、入力フォーカス時のSafariの意図しない自動ズームを防ぐ。

### 8.2 情報配置

画面上部の操作順は次のとおりとする。

1. 実施日
2. この日のメニュー
3. 種目名検索と使用器具ボタン
4. `実施済みのみ`、選択中器具、件数、条件クリア
5. 種目カード一覧
6. 既存の固定 `記録して終了`

日付入力、`昨日`、`今日` はiPhone 16 Pro幅で同一行に収める。ラベルや補足情報のためだけに入力コントロールを不必要に改行しない。

### 8.3 モバイルワイヤーフレーム

```text
┌──────────────────────────┐
│ 実施                      │
│ [ 2026/08/09 ] [昨日][今日]│
│ この日のメニュー           │
│ [ 種目マスタ（全種目）  ▾ ]│
│ [種目名で検索        ×][器具]│
│ [実施済みのみ] 12 / 84種目 │
│ ─ 選択中器具チップ → ───── │
├──────────────────────────┤
│ [実施済み] ベンチプレス     │
│ 胸（中部）・バーベル         │
│ 直近 80kg × 8回 × 3set      │
│ [前回値を入力]              │
│ [重量] [回数] [セット]      │
│ [メモ                     ] │
├──────────────────────────┤
│ 次の種目カード…             │
│                            │
│ [      記録して終了       ] │
│ [下部ナビゲーション]        │
└──────────────────────────┘
```

### 8.4 改行と省スペース

- ページ全体の横スクロールを禁止する。
- 種目名は原則1行、長い場合は最大2行までとし、それ以上は省略する。省略時もアクセシブルな名称を保持する。
- 筋肉ターゲットと器具は1行の要約とし、長い場合は省略する。詳細は種目カードの展開領域で確認できるようにする。
- 重量・回数・セット数の3入力はiPhone 16 Pro幅で同一行に維持する。
- 主要操作ボタンは短いラベルを使い、文字単位の不自然な折り返しを禁止する。
- フィルター領域は通常時に2行程度へ収め、器具候補一覧は常時展開しない。
- 選択中器具チップは横スクロールとし、縦方向の占有量を一定にする。

### 8.5 操作性

- 種目名入力から一覧更新まで、クライアント側処理では知覚できる遅延を発生させない。
- ボトムシート表示中は背面スクロールを固定する。
- ボトムシートは下方向スワイプ、閉じるボタン、`適用` で閉じられるようにする。
- `記録して終了` はキーボード、ボトムシート、下部ナビゲーション、ホームインジケータと重ならない。
- トグル、選択、クリア、入力には押下・フォーカス状態を表示する。
- 破壊的操作ではないフィルター変更や表示切り替えでは確認ダイアログを出さない。

### 8.6 アクセシビリティ

- すべての入力、トグル、器具チェックボックスに可視ラベルを付ける。
- `実施済みのみ` は色だけで状態を表さず、文言、チェック状態、`aria-pressed` または同等属性で通知する。
- 検索結果件数と0件状態をスクリーンリーダーへ通知する。
- ボトムシート表示時はフォーカスをシート内へ移し、閉じたときは器具ボタンへ戻す。
- キーボード操作でも候補選択、解除、適用ができること。
- 文字サイズを拡大しても入力欄やボタンの文字が欠けず、主要操作が使用できること。

## 9. 状態別表示

| 状態 | 表示・操作 |
| --- | --- |
| 読み込み中 | 既存カード形状に近いスケルトンまたは読み込み表示。フィルター操作による二重要求を防ぐ |
| 全種目0件 | `登録済みのトレーニング種目がありません` とメニュー管理への導線 |
| 絞り込み0件 | `条件に一致する種目がありません`、`条件をクリア` |
| 実施済み0件 | `この日の実施済み種目はありません` |
| APIエラー | 入力済み下書きを保持し、再試行ボタンとエラー概要を表示 |
| 入力中カードがフィルター外 | `入力中 n件` 導線を表示し、保存対象が存在することを隠さない |
| 12件入力済み | 既存の上限メッセージを表示し、13件目の開始を防ぐ |

## 10. データ・API要件

### 10.1 表示範囲

実装では、少なくとも次の表示範囲を型として明示的に区別する。

```text
menuSet(menuSetId)  実在メニューセット内
master              有効な全トレーニング種目
completed(date)     対象日のメニューセット横断実施済み種目
```

予約文字列を実在メニューセットIDとして扱わず、表示範囲とIDを別フィールドで管理する。

### 10.2 実施画面取得API

現行の `GET /training-session-view` を後方互換のまま拡張するか、同等の専用取得APIを追加する。レスポンスは表示範囲に応じて次を返せること。

- `viewMode`: `menuSet | master | completed`
- `resolvedMenuSet`: 実在セット選択時だけ値を持ち、仮想表示時は `null`
- `items`: 表示対象種目
- 種目マスタ情報
- メニューセット固有処方。仮想表示時は未設定を表現できること
- 対象日以前の直近実績
- 対象日の実施済みフラグ
- 対象日の実施回数
- 対象日の最新実績スナップショット
- 読み取り専用履歴項目かどうか

既存の `todayDoneTrainingMenuItemIds` は活用可能だが、同日実施回数、同日の最新実績、無効化済み種目の履歴表示に必要な情報を追加する。

### 10.3 完全性と性能

- 「全種目」はページングを含む全件を意味し、一部ページのみ返してはならない。
- フィルターは取得済みの基本母集団に対してクライアント側で行い、入力1文字ごとにAPI要求しない。
- 同一表示範囲・対象日の再表示では、下書きの整合性を壊さない範囲で取得結果を再利用してよい。
- 200件の有効トレーニング種目を基準に、一覧取得完了まで通常2秒以内、入力後の絞り込み結果更新は100ms以内を目標とする。
- 種目ごとの無制限な逐次取得を避け、一覧件数に比例して待ち時間が過度に増加しない構成とする。

### 10.4 保存API

- 実績保存APIは、`sourceTrainingMenuSetId` と `sourceTrainingMenuSetItemId` がない有効なトレーニング種目の保存を受け付ける既存仕様を維持する。
- 本人所有かつ保存時点で有効な `trainingMenuItemId` であることを検証する。
- 仮想のメニューセットIDを受け付けたり永続化したりしない。
- 実在セット由来の既存保存形式を変更しない。

## 11. 既存仕様との整合

- 実在メニューセット選択時の優先順位計算を維持する。
- フィルター後も、実在セットの `優先 n` は元の優先順位を表示し、表示中だけで番号を振り直さない。
- 一時セットはセット内登録順を維持する。
- 前回値、セット値、セット詳細、メモ、説明の既存機能を維持する。
- メニュー切り替え時に確認を表示せず、下書きを保持する。
- 日付変更時の下書き破棄確認を維持する。
- トレーニングとリカバリーを1回の保存へ混在させない。
- 対象日に既存実績がある場合の「追加記録」表示を維持する。

## 12. 受入条件

### 12.1 仮想種目マスタ

- [ ] メニュー選択UIに `種目マスタ（全種目）` が表示される。
- [ ] 選択すると、セット未所属を含む有効な全トレーニング種目が表示される。
- [ ] 101件以上存在しても、APIの先頭100件だけに欠落しない。
- [ ] リカバリー項目は全種目一覧へ混入しない。
- [ ] 選択・保存後も、仮想メニュー用のメニューセットレコードが作成されない。
- [ ] 仮想IDが実績へ保存されない。
- [ ] 直近実績なしの種目も手入力で保存できる。

### 12.2 フィルター

- [ ] 種目名の部分一致で即時に絞り込める。
- [ ] 全角・半角、英字大小、ひらがな・カタカナの差を吸収する。
- [ ] 空白区切りの複数語がAND一致する。
- [ ] 器具候補をフリー入力で絞り込める。
- [ ] 器具を複数選択でき、器具間はORになる。
- [ ] 種目名と器具はANDになる。
- [ ] 種目名だけ、器具1件、器具複数、両条件、全解除の各ケースで件数が正しい。
- [ ] フィルターで非表示になった下書きが失われない。

### 12.3 実施済みのみ

- [ ] `実施済みのみ` をONにすると、対象日の全メニューセットを横断した実施済み種目が表示される。
- [ ] 選択中セットに含まれない実施済み種目も表示される。
- [ ] 同じ種目の同日複数実績は1カードに集約され、件数と最新値を確認できる。
- [ ] 日付変更に合わせて実施済み一覧が更新される。
- [ ] 種目名・器具フィルターを実施済み一覧にも適用できる。
- [ ] OFFにすると、元のメニュー選択へ戻る。
- [ ] 表示切り替えだけで保存済み実績が変更されない。

### 12.4 iPhone 16 Pro UX

- [ ] `402 × 874 CSS px` の縦向きでページ全体の横スクロールがない。
- [ ] 日付、昨日、今日が同一行に収まる。
- [ ] 重量、回数、セット数が同一行に収まり、入力可能である。
- [ ] 主要操作のタップ領域が44×44 CSS px以上である。
- [ ] 入力フォーカス時に意図しない画面ズームが発生しない。
- [ ] 器具ボトムシートとソフトウェアキーボードが操作ボタンを隠さない。
- [ ] `記録して終了` と下部ナビゲーションが重ならない。
- [ ] 長い種目名、器具名、筋肉名でも不自然な文字単位改行やレイアウト崩れがない。
- [ ] 文字サイズ200%相当でも主要操作が可能である。

## 13. テスト観点

- 実在セット、仮想種目マスタ、実施済みのみの相互切り替え
- セット未所属、複数セット所属、一時セット所属の種目
- 有効、無効、削除済み種目と履歴スナップショット
- 対象日0件、1件、同一種目複数件、複数訪問
- 種目数0件、100件、101件、200件以上
- 日本語IME入力中と変換確定後
- 全角・半角、英字大小、ひらがな・カタカナ、複数語
- 器具0件、1件、複数件、候補検索、選択後の候補検索解除
- フィルター中の入力、メニュー切り替え、日付切り替え、下書き復元
- 保存上限12件と、フィルター外にある入力中項目の可視化
- iPhone 16 Pro Safari、ホーム画面追加後のPWA表示、Safari可変ツールバー表示中
- VoiceOver、外付けキーボード、文字サイズ拡大、色以外の状態識別

## 14. 実現方針

1. 表示範囲を実在メニューセットIDから分離した型へ変更する。
2. 実施画面取得APIを、実在セット、全種目、対象日実施済みの3範囲へ対応させる。
3. 全種目取得のページングと、対象日の実績集約をバックエンドまたはAPIクライアントで完全に処理する。
4. 種目カードのデータを「セット固有処方あり／なし」「編集可能／履歴のみ」で表現できるようにする。
5. フロントエンドに検索正規化、AND/OR判定、件数表示、フィルター状態保持を追加する。
6. 器具複数選択をiPhone向けボトムシートとして実装する。
7. 下書きを表示範囲から独立させ、特殊表示でも既存下書きを再利用できるようにする。
8. iPhone 16 Proの実機相当ビューポートとPlaywrightで、操作、改行、safe area、キーボード周辺を検証する。

## 15. 承認時に確認する前提

本書は次の3点を確定案としている。異なる意図がある場合は、実装前に本書を修正する。

1. `種目マスタ（全種目）` と `実施済みのみ` はトレーニング種目だけを対象とし、リカバリー活動は対象外とする。
2. 種目マスタにはセット固有処方がないため、未実施種目は入力欄を空で開始し、「設定値を入力」は表示しない。
3. `実施済みのみ` は対象日の実績を `trainingMenuItemId` 単位で1カードに集約し、同日複数回の場合は件数と最新値を表示する。
