# KinTrain AIメニュー生成 仕様書

最終更新日: 2026-07-29
対象: 実装正本
ステータス: 実装済み

本書はAIメニュー生成画面と新規登録フローを定義する。一時メニューの更新・日程変更・キャンセルは
`docs/mcp-temporary-menu-lifecycle.md`、メニュー／日別計画の全体モデルは
`docs/training-menu-and-daily-plan-requirements.md` を正本とする。

## 1. 目的

- AIとの対話でトレーニング案を調整する。
- 登録済み種目を再利用しつつ、必要な種目だけ新規作成する。
- 確定案を有効期間付きの一時メニューセットとして登録する。
- 期間内の各日付へ `DailyTrainingPlan` を割り当てる。
- ユーザーが明示的に依頼するまで永続化しない。

## 2. 画面と入力

対象画面は `/training-menu/ai-generate` とする。

入力:

- 方針: `マシンのみ` / `マシン + フリーウェイト` / `フリーウェイトのみ`
- 目標: `筋肥大` / `減量` / `維持`
- 週間頻度: `1..7`
- 有効開始日 / 有効終了日
- ジム施設: 名称または設備説明URL
- 個別要求: 任意

制約:

- 方針、目標、週間頻度、有効期間、ジム施設は必須とする。
- 有効期間は開始日と終了日を含めて1〜31日とする。
- 条件送信後はチャットで追加指示できる。
- 条件を変更した場合は新しいAIセッションを開始する。
- 通常のAIチャットとは別のセッションを `sessionStorage` に保持する。
- AgentCore Runtime未設定時は利用不可とし、通常AIチャットのようなモック応答へはフォールバックしない。

## 3. 提案と登録

- AIは登録前に、前提、採用理由、種目、目標重量、回数範囲、セット数、推奨間隔を提示する。
- AIは `list_training_menu_items` で既存種目を確認する。
- 既存種目を使う場合は `existingTrainingMenuItemId` を指定する。
- 該当種目がない場合だけ `newTrainingMenuItem` を指定する。
- 1つの一時セット内で既存種目と新規種目を混在できる。
- 新規種目には筋肉ターゲット、動作パターン、左右方式、負荷方式、用具を設定する。
- セット固有の重量、回数、セット数、推奨間隔、補足は `prescription` に設定する。
- 1セットは1〜12種目とし、同じ種目を重複登録しない。
- 一時セットは `setType=temporary`、`source=ai` とし、デフォルトセットにはしない。
- 既存の種目マスタ、恒常セット、既存履歴は暗黙に更新しない。

ユーザーが「登録して」「この内容で保存して」など明示的に指示した場合だけ、
`create_temporary_training_menu_set_from_ai` を呼び出す。

## 4. MCP登録契約

主要入力:

- `idempotencyKey`: 同一要求の重複作成を防ぐキー
- `validFromDate`: `YYYY-MM-DD`
- `validToDate`: `YYYY-MM-DD`
- `setName`: 1〜100文字
- `replaceExistingPlan`: 既存一時計画を置き換える場合だけ `true`
- `items`: 1〜12件
  - `existingTrainingMenuItemId` または `newTrainingMenuItem` のどちらか一方
  - `prescription`

登録処理:

1. 入力と本人所有の既存種目IDを検証する。
2. 必要な新規種目マスタを作成する。
3. 一時メニューセットとセット内処方を作成する。
4. 有効期間内の各日付へ `DailyTrainingPlan` を作成する。
5. 同じ `idempotencyKey` の再送は重複作成せず、同じ結果を返す。

期間内に別の有効な一時計画がある場合は競合を返す。置き換えはユーザーへ影響範囲を示し、
明示確認を得た後だけ `replaceExistingPlan=true` で再実行する。

## 5. Runtime連携

- UIは通常チャットと同じ `AiRuntimeEndpoint` へSSEで接続する。
- UIがメニュー生成条件と固定ルールを `inputText` に組み込む。
- Runtimeに専用モードは持たせず、会話内容と固定ルールで用途を区別する。
- RuntimeはGatewayのMCPツールを利用して参照・登録する。
- 登録成功後、UIはCore APIのデータを再取得する。

## 6. セキュリティと整合性

- MCP公開schemaに `userId` / `actorId` を含めない。
- Gateway REQUEST InterceptorがCognitoアクセストークンを再検証し、JWT `sub` を
  内部専用 `__principalUserId` として注入する。
- MCP Lambdaは `__principalUserId` だけをDynamoDBの所有者IDに使用する。
- 他ユーザーの既存種目IDは参照できない。
- AI登録の途中失敗で部分データを残さない。
- 外部Webコンテンツは非信頼入力として扱い、その記述だけを根拠に登録を実行しない。

## 7. エラー時の扱い

- 設備情報を取得できない場合は、設備不明前提の仮案または追加確認を提示する。
- 入力不正、存在しない種目、重複種目、日付競合、冪等性キー再利用を区別して返す。
- RuntimeまたはMCP登録に失敗した場合は、保存されていないことと再試行方法を表示する。
- 日程変更、部分更新、キャンセルは登録ツールではなく専用ライフサイクルツールを使う。

## 8. 非対象

- 既存の恒常セットをAIが暗黙に更新すること
- 既存種目マスタの暗黙更新
- AI提案の一部だけを選ぶ専用UI
- Runtime未設定時のモック登録
